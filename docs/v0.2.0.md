# Clipform v0.2.0 — Planning

**Theme:** Make a growing library effortless to manage.

v0.1 proved you can *save* things into a Figma file. v0.2 makes a library of 100+ refs feel as light as a library of 10. Every Tier-1 feature targets a specific friction point a serious user hits between 50 and 500 refs.

---

## Success criteria

The release ships when a user with **200+ references** can:

- [ ] **Cluster** their library into auto-suggested collections without writing tags by hand
- [ ] **Tag or move 20 refs at once** without opening each detail drawer
- [ ] **Sort** the grid by date / similarity / dominant color, and adjust card density without breaking the layout
- [ ] **Combine filters** — find "warm refs in the Branding collection that contain a face" in one shot
- [ ] **Crop messy paste-ins** before saving, so the library stays clean

A useful self-check: can a teammate of mine browse my 200-ref library and find what they need in under 10 seconds, without ever asking me?

---

## Tier 1 — must-have

### 1. Smart auto-collections

> "Found 8 visually similar refs. Make a collection?"

When the library has unindexed similarity structure (≥6 refs that cluster together but aren't in a collection), surface a suggestion banner in the sidebar. One click creates the collection and assigns the members.

**How:**
- K-means on stored CLIP embeddings, `k = floor(N / 12)` capped at 6
- Filter clusters by intra-cluster similarity ≥0.72 (above pure-noise threshold)
- Suggest a name from the cluster's top tags (or fall back to "Cluster N")
- One-click dismiss per cluster, persisted in `clientStorage`

**Files:** `ui.html` (clustering in the UI iframe — embeddings already in state), small sandbox helper for "create collection + bulk-assign".

**Risk:** k-means quality depends on embedding count. With <30 refs, suggestions look random. Gate the feature behind `state.refs.length ≥ 30`.

### 2. Bulk operations in the action bar

The selection action bar today only offers Arrange + Clear. Add:

- **Tag all** — single tag input applies to N refs
- **Move to collection** — collection picker reassigns N refs
- **Delete all** — with a "click again to confirm" pattern (no `confirm()` — blocked in Figma iframe)

**How:** sandbox gets `bulk-tag`, `bulk-move`, `bulk-delete` message handlers. Each iterates the selected refIds, modifies pluginData, pushes the library once at the end (not per-ref) for speed.

**Risk:** very fast click-through could trigger pushLibrary mid-update. Debounce the push to 100ms.

### 3. Sort + card-size controls

Top bar gains two compact controls right of the search input:

- **Sort ▾** — Newest · Oldest · Most reacted · Similar to selected · By dominant color
- **Zoom slider** — 2 / 3 / 4 column grid

**How:** purely UI-side. Sort modifies the comparator in `visibleRefs()`. Zoom toggles a CSS class on `.grid` that changes `column-count`. Both states persist in `clientStorage`.

**Risk:** "By dominant color" needs a stable color-order function — use the most-saturated swatch's hue from each ref, sort hue clockwise.

### 4. Combined filters

Currently filters are mutually exclusive (text query OR similar mode OR tag OR color). Make them additive:

- Text query stays applied while you click a collection
- Color filter narrows the AI search results
- The banner shows all active filters with individual clear buttons

**How:** `visibleRefs()` becomes a pipeline that always applies tag, color, collection filters, then either keeps order OR applies a similarity sort if a query/similar mode is active.

**Risk:** the "Clear" button currently clears one mode. Replace with per-filter chips that each have their own ✕.

## Tier 2 — nice-to-have

### 5. Crop-on-save

When a user pastes a screenshot with chrome (browser bars, etc), a quick crop saves the library from noise.

- Before `add-reference` fires, show a small crop overlay over the pasted image
- Two outputs: "Save as-is" or "Save crop"
- Crop region stored in pluginData for re-edits

Implementation is mostly UI canvas work; no sandbox changes.

### 6. Library health panel

Settings drawer gains a small section:
- Total refs · indexed vs unindexed
- Storage estimate (sum of pluginData JSON lengths)
- "Re-index all" button (forces embedding recompute)
- "Find duplicates" (cosine sim ≥0.97 across all pairs)

Useful for power users to keep their library lean.

### 7. Keyboard shortcuts

- `/` — focus the search input
- `⌘V` — paste from clipboard (already works, but make it discoverable in empty state)
- `Esc` — close drawer / clear selection
- `←` `→` — already work in lightbox, extend to the detail drawer

## Out of scope (and why)

| Idea | Why not in 0.2 |
|---|---|
| Browser extension companion | Separate codebase, separate distribution flow (Chrome Web Store review). Treat as v0.3 or its own project. |
| Video / GIF references | Figma's image-fill API doesn't render animated content. Static first-frame is the most we could do, and that's worse than just a still. |
| Cloud sync / accounts | The wedge of v0.1 is "no backend, no login." Don't compromise that. |
| Public Figma Community release | Requires plugin-store review, screenshots in specific dimensions, etc. Worth doing once the feature surface stabilizes — likely after v0.3. |

## Engineering refactors needed

Some Tier-1 features want shape changes that v0.2 is a natural moment to make:

- **Filter pipeline** — `visibleRefs()` currently has nested if-branches. Refactor to an array of filter functions composed into a single pipeline so adding "by reaction count" or "by author" later is one line.
- **Embedding worker** — clustering 200 refs synchronously will jank the UI for ~200ms. Move CLIP inference *and* k-means into a Web Worker so it never blocks paint.
- **PluginData migration** — new fields (clusterId? cropRect?) need to default cleanly on old refs. Bump a `schemaVersion: 2` field on each ref written by 0.2; on read, fill missing fields with defaults.
- **Test harness** — currently zero automated tests. Before 0.2 ships, add a tiny Node test runner that loads `code.js` in a Figma mock and exercises every message handler. Nothing fancy — even 30 lines of mock + 10 cases catches a lot of regressions.

---

## Sequencing

Suggested implementation order — each step ships independently and the plugin is usable at every step:

1. Refactor filter pipeline (no user-visible change) → catches regressions in steps 2–5
2. **Combined filters + per-filter chip clears** (Tier 1.4) → small surface, immediate UX win
3. **Sort + card-size controls** (Tier 1.3) → reuses the filter pipeline
4. **Bulk ops in action bar** (Tier 1.2) → builds on existing selection model
5. **Smart auto-collections** (Tier 1.1) → requires the worker refactor first
6. Crop-on-save (Tier 2.5) → independent
7. Library health panel (Tier 2.6)
8. Keyboard shortcuts (Tier 2.7) → cleanup polish

Cut a v0.2.0 release after step 5. Tier-2 items can ship as 0.2.x patches.

## Open questions

- **Cluster suggestion frequency** — show on every plugin open? Once per session? Once per N new refs? Lean toward "once per session, dismissible per cluster."
- **Sort persistence** — should sort be per-collection (i.e. each collection remembers its preferred sort) or global? Probably global for v0.2, per-collection in v0.3.
- **Bulk delete affordance** — "click again to confirm" vs. an inline undo toast. Toast is friendlier but more UI to build. Start with double-click confirm.
- **Crop tool** — write our own canvas-based cropper (~200 lines), or load a library (smaller code, network dependency). Lean toward writing our own — fits the "no dependencies" ethos.
